# Backend-Note-vs-Display Audit — Biomarkers, Stim Optimizer, Closed-Loop Deployment

**Method used.** Grepped all three backend modules for text-generating fields (`notes`, `why`, `human_text`, `*_note`, `detail`, `describe`, `reason`, `caption`, `headline`, `footer`, `sentence`), then grepped the matching frontend directories for each field name to find the printing component, then read the component's render logic against the generator's wording. In addition, ran a live probe (`BRAVO/_agent_bridge/_referent_bnd_probe.py`, disposable, gitignored, not committed) against the three real endpoints for RCS08 (uid `2e3c75c00d7f4f37b53a048d195f11da`) and flattened all 1,054 long string values into `/private/tmp/.../scratchpad/full_dump.txt`, so every sentence quoted below is the live value, not a guess at what the code would produce.

**Coverage note, stated up front per the coordinator's instruction.** Given the volume of text-generating fields across three modules (over 400 distinct field paths in the live corpus), this pass is not exhaustive. Reached in full: `Biomarkers/routines/analytics.py`'s band-by-length sweep notes (`BEST_OF_WINDOWS_OPTIMISM_NOTE`, `AUC_REFERENCE_NOTE`, `AUC_DIRECTION_NOTE`, `DEVICE_SPECTRUM_AXIS_NOTE`, `_sweep_notes`, `pain_split_rule`) against `BiomarkerHeatmapGrids.js`/`gridReadouts.js`; `ClosedLoopDeployment`'s `ReliableChangePanel.js` against `reliable_change.*`; `ThreeSourceResponsePanel.js` against `three_source_response.comparisons[]` and `three_source_pooled.*`; `DeviceRuleLedger.js` against `constraints.py`'s `human_text`; `EvidenceTrianglePanel.js` against `coherence.note`; `PrescriptionPanel.js` against the T3–T6 note fields (`design_rule_note`, `occupancy_note`, `startup_bias_note`, `robustness_note`); `TitrationSessionCard.js` and `CurrentMapCard.js`/`DecisionStrip.js` against `titration_plan.*` and the two-stage gate's per-hemisphere text. **Not reached in the time available**: `BandSweepGridPanel.js`, `DeploymentRocPanel.js`, `LsbPowerPanel.js`, `PsdLsbPanel.js`, `ConversionModelPanel.js`, `EraRefitPanel.js`, `WhatWouldChangeThis.js`, `SensingEvidenceTable.js`, `BandResponseStrip.js`, `ExcludedSettingsChart.js`, `GainBar.js`, `stage_gate.py`'s condition-detail bodies beyond `openloop_choice_resolved`, `stage1_openloop.py`'s `_rate_stratum_resolution` sentence in its printed context, and the full 51-row body of `constraints.py`'s `human_text` (only the D01/D02 pair and a sample of the rest were read against the ledger's rendering).

### 3. Duplicate device-spectrum sentence — backend's own sentence in the drawer vs. frontend's independently-computed sentence in the always-visible caption
- **Field:** the tail entry of `biomarkers.band_time_sweep.<contact>.notes[]` (index 7 or 8, after `_sweep_notes`'s own list)
- **Generator:** `BRAVO/modules/Biomarkers/routines/analytics.py:6141-6146` — appends *"%d of this contact pair's matched pain reports were answered from the device's own FFT snapshots rather than the voltage trace, and the most affected cell drew %.0f%% of its reports that way. [DEVICE_SPECTRUM_AXIS_NOTE]"* to the `notes` list only `if n_dev_reports`.
- **Printer:** `BiomarkerHeatmapGrids.js:116-130` (`bulletsFor`) puts this at the tail of the fold/drawer via `notes.slice(3)`.
- **Second, independent generator of the same fact:** `Client/src/views/Reports/Biomarkers/gridReadouts.js:124-135` (`deviceSpectrumBullets`), which recomputes the identical fact **from the raw grid arrays**, not from the backend's own sentence, and is drawn in the **always-visible orange caption** above the grids (`BiomarkerHeatmapGrids.js:598`).
- **On screen:** both — one instance always visible (frontend-composed), one instance in the fold (backend-composed).
- **Mismatch in one sentence:** this is not a wrong referent (both correctly describe rows as lengths-of-signal and correctly name the device-spectrum share), but it is the same fact authored twice by two different code paths that could silently drift apart the next time either is edited — exactly the failure mode this project's own decision log (§2 principle 5, and CLAUDE.md's DRY principle) warns about.
- **What it should say:** one of the two should be deleted; the frontend's `deviceSpectrumBullets` is the one actually driving the visible page, so the backend's tail-appended sentence in `notes` is the redundant one.
- **Fix:** **backend** (stop appending the device-spectrum sentence to `notes` in `analytics.py`, since the frontend already computes and displays it independently and correctly).
