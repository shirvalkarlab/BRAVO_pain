# Fixel development integration — September 18, 2026

This adaptation covers the remaining behavior from Fixel `b2412b0e` relative to
Aditya `071b2ef1`; it preserves Aditya's existing frontend and customized summary.
The previously accepted participant-table append and therapy single-session guard
remain intact.

- Device JSON queries use containment on supported database engines and the
  equivalent key lookup on SQLite. Participant filters and existing authorization
  remain in place. Fitbit timeline entries now sort chronologically with their
  values attached.
- Alignment edits apply atomically to synchronized record types sharing the
  selected source. Other source/type records and native timestamps are untouched;
  invalid/nonfinite offsets fail before any write. Updating the participant
  revision invalidates dependent work, and a robust post-commit cache callback
  logs cache failures without incorrectly reporting that a committed edit failed.
- MDAT v3 is an explicit upload format. Generic `.mdat` uploads detect the packet
  format and continue supporting v2. The v3 parser validates packet boundaries
  and rates, retains native packet timestamps, and separates discontinuous
  channel intervals. It does not truncate channels to a common length, reuse a
  different channel's clock, or turn gaps into zero-valued observations. Overlaps
  and out-of-order packet timestamps fail explicitly. Stored source bytes are
  retained; sample-content hashes and participant identity govern deduplication.
- New BIDS datasets use four-digit subjects. Existing mapped subject labels stay
  unchanged. History deduplication compares device identity and record content
  across uploads; corrected records and different devices remain distinct. The
  generated `sourcedata/bravo/sub-*_history_sources.json` records every reporting
  source. Re-export removes only generated history tables that become empty.
- BIDS event onsets now retain physical elapsed seconds from reporting-session
  start. They can legitimately be negative or extend beyond the visit. Neither
  legacy clamping nor upstream logarithmic compression is applied. This is an
  intended export semantic correction; original events and live scientific data
  are not rewritten.

`Server/test_fixel_20260918.py` supplies synthetic decoder, ORM/storage, atomic
alignment, real Fitbit-output, stable-label, deduplication/provenance and re-export
regressions. Full application/CI and real-data acceptance are separate. MDAT tests
establish behavior for the supplied packet convention; a real device fixture is
still needed to independently confirm vendor packet timestamp semantics. No
production data import, alignment edit or BIDS migration is performed by this
source integration.
